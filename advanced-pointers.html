Advanced Pointers

You know what a pointer is and how to use one with arrays, functions and the heap. This lesson covers the next layer: pointers that point at other pointers, arrays full of pointers, const, the type-less void *, and pointers to functions. None of it needs new rules. Each one is the same idea, "a variable that holds an address", applied one more time.

Pointers to pointers

A pointer is a variable, so it lives somewhere in memory and has an address of its own. A variable that stores that address is a pointer to a pointer. Read the declaration right to left from the name, just like before:

Each * you apply follows one arrow. pp is the address of p, *pp is p itself (the address of x), and **pp is x.

ExpressionTypeMeaning
ppint **the address of p
*ppint *the value of p, i.e. the address of x
**ppintthe value of x

You could keep going (int *** is legal), but in practice you'll rarely see more than two levels. The interesting question is not "how deep can it go" but "why would I ever want two?"

Why: letting a function change the caller's pointer

In Pointers & Functions you saw that C passes every argument by value. To let a function change an int in the caller, you pass an int *. The exact same logic applies one level up: to let a function change an int * in the caller, you pass an int **.

The pattern generalises. Whenever a function needs to reassign a pointer that belongs to its caller (allocate it, reallocate it, advance it, set it to NULL), take a pointer to that pointer. You'll use exactly this in the linked-list capstone, where push_front(&head, 5) has to change which node head points to.

The alternative: return the pointer

Often it's simpler to just return the new pointer: int *make_int(int value), used as p = make_int(42);. That's what malloc itself does. Out-parameters (int **out) shine when the return value is already used for something else, such as an error code, or when a function produces several pointers at once.

Arrays of pointers

An array can hold any type, including pointers. The most common case is an array of strings:

Each element of names is a const char * pointing at a string literal stored elsewhere. The strings can have different lengths, because the array only stores the addresses. (const is there because string literals must not be modified. More on const below.) Compare that with a 2D char array, char names[4][7], where every row is a fixed 7 bytes whether you need them or not.

Note the subscripting: names[i] is a const char *, and names[i][0] is a char, the first letter of that string. When an array of pointers is passed to a function it decays, as arrays do, into a pointer to its first element, which is a pointer to a pointer: const char **.

argv: the array of pointers you've been ignoring

main has a second standard form that receives the program's command-line arguments:

  • argc ("argument count") is how many strings there are, including the program's own name.
  • argv ("argument vector") is an array of char *. argv[0] is the program name (by convention), argv[1] is the first real argument, and so on.
  • The standard guarantees argv[argc] is a null pointer, so you can loop either by count or until NULL.

Dynamically allocated 2D arrays

A built-in 2D array like int grid[3][4] needs its size fixed at compile time and lives on the stack. When the dimensions come from user input, a common approach is an array of row pointers: allocate an array of int * (one per row), then allocate each row separately.

Why does grid[r][c] work? grid[r] means *(grid + r): step r pointers along and read one. That gives an int * to the start of row r, and [c] indexes into that row. Same syntax as a real 2D array, quite different memory underneath: the rows are separate heap blocks that may be anywhere.

Two details matter here:

  • Free in the reverse order you allocated. If you free(grid) first, the row pointers are gone and you can't legally read grid[r] any more to free the rows.
  • Clean up partial failures. If row 2's malloc fails, rows 0 and 1 (and grid itself) must still be freed. That's why make_grid calls free_grid(grid, r) with the number of rows that actually succeeded.
The one-block alternative

Row pointers make ragged arrays (rows of different lengths) easy. If every row is the same length, you can instead allocate one block, int *cells = malloc(rows * cols * sizeof *cells);, and index it as cells[r * cols + c]. That's one malloc, one free, no partial-failure cleanup, and the data is contiguous, which is faster to loop over.

const and pointers

With a pointer there are two things that could be read-only: the pointer (where it points) and the data (what it points to). Where you put const decides which. The trick is again to read right to left from the name:

DeclarationRead right to leftChange *p?Change p?
int *pp is a pointer to intyesyes
const int *p
int const *p		p is a pointer to an int that is constnoyes
int *const pp is a const pointer to intyesno
const int *const pp is a const pointer to a const intnono

The rule: const applies to whatever is immediately to its left, or, if nothing is on its left, to what's on its right. So const int * and int const * are identical, and in int *const p the const sits right before the name, locking the pointer itself.

Why const pointers matter: function contracts

By far the most common use is in function parameters. A const char * parameter is a promise to the caller: "I will read your string but not modify it." That's why the standard library declares size_t strlen(const char *s) and char *strcpy(char *dest, const char *src): from the signature alone you can tell which argument gets written.

Notice that word isn't const but we passed it to a const char * parameter. Adding const is always allowed implicitly. Removing it requires a cast, and actually modifying an object that was defined const is undefined behaviour. Also note that const int *p only stops you from modifying the int through p; the int itself may change by other means.

void *: the generic pointer

A void * is a pointer to "something, type unknown". Any object pointer converts to void * and back again without losing information, and in C these conversions happen implicitly. You've already met one: malloc returns void *, because it has no idea what you'll store in the block.

Since the compiler doesn't know what a void * points to, it can't let you use it directly:

  • You can't dereference it. *anything is an error, because how many bytes would it read?
  • You can't do arithmetic on it in standard C. (GCC allows void * arithmetic as an extension, treating it like char *, but portable code doesn't rely on that.)

To work with the bytes, convert to a typed pointer first. The usual choice for "raw bytes" is unsigned char *, since C lets you inspect any object as an array of unsigned char. Generic means unchecked

The price of void * is that the compiler stops checking types for you. swap_any(&i1, &d1, sizeof d1) compiles without complaint and writes 8 bytes into a 4-byte int. When you use void *, getting the types and sizes right is your job. (Also, function pointers are a separate family: standard C doesn't guarantee you can store one in a void *.)

Function pointers

Compiled functions live in memory too, so they have addresses, and you can store those addresses in variables. A function pointer lets you choose which function to call at run time, or hand a function to another function to call later.

Read int (*op)(int, int) from the name outwards: op is a pointer (*op) to a function taking (int, int) that returns int. The parentheses around *op are essential: int *op(int, int); declares a function named op that returns an int *. The pointer's type must match the function's signature exactly.

Sorting anything with qsort

The standard library's qsort (in <stdlib.h>) combines both ideas of this lesson: void * so it can sort any type, and a function pointer so you decide the order:

You give it the array, how many elements, how big each one is, and a comparator. qsort calls the comparator with pointers to two elements, and it must return a negative number if the first should come before the second, zero if they're equal, and a positive number if the first should come after.

Don't write return x - y;

You'll see comparators that return *(int *)a - *(int *)b. It looks clever and usually works, until it doesn't: with x = INT_MAX and y = -1 the subtraction overflows, which is undefined behaviour and in practice yields a negative number, so the sort silently comes out wrong. (x > y) - (x < y) is just as short and always correct. To sort in descending order, swap the roles: (x < y) - (x > y).

The string-comparator trap

When sorting an array of char *, each element is a pointer, so the comparator receives a pointer to a pointer. Writing strcmp(a, b) directly compiles (both are void *) but compares the bytes of the pointers themselves, as if they were text. Always ask: "what is one element of my array?" The comparator gets a pointer to that.

Exercises

Allocate through an out-parameter

Write void make_array(int **out, int n). It should allocate an array of n ints, fill it with the squares 1, 4, 9, ..., and store the array's address in the caller's pointer through out. If malloc fails, set the caller's pointer to NULL. The provided main should then print 1 4 9 16 25 36.

Hint

Build the array in a local int *a = malloc(n * sizeof *a);, fill it if it isn't NULL, then do *out = a;. Writing out = a would only change the local parameter (and wouldn't type-check anyway).

Apply a function to every element

Write void apply(int *a, size_t n, int (*f)(int)), which replaces every element a[i] with f(a[i]). Also write int add_one(int x). Then, in main, apply twice to the array, print it, apply add_one, and print it again, so the output is exactly:

2 4 6 8 10
3 5 7 9 11
Hint

Inside apply, call the function pointer like a normal function: a[i] = f(a[i]);. To pass a function, use its name without parentheses: apply(nums, n, twice);. Writing twice() would try to call it.

Sort a leaderboard with qsort

Write the comparator by_score so that qsort orders players by score, highest first, and players with equal scores alphabetically by name. Don't use subtraction to compare the scores.

Hint

Each element is a struct Player, so the comparator gets pointers to structs: const struct Player *pa = a;. For descending order, return a negative number when pa's score is bigger: (pa->score < pb->score) - (pa->score > pb->score). If the scores are equal, return strcmp(pa->name, pb->name).

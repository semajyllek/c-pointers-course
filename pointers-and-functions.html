Pointers & Functions

A function in C only ever gets copies of its arguments. Pointers are how you get around that: pass an address, and the function can reach back into the caller's memory. This lesson covers the patterns you'll use constantly, from the classic swap to output parameters, plus the one mistake every C programmer makes at least once: returning a pointer to something that no longer exists.

Recap: C passes by value

Back in the Functions lesson you saw that a parameter is a brand-new local variable, initialised with a copy of the argument. Whatever the function does to that copy stays inside the function. Here's the consequence that motivates this whole lesson:

Inside the function the swap worked. But a and b were copies of x and y, living in broken_swap's own stack frame. When the function returned, that frame was thrown away, and x and y were never touched.

Swap, done right

The fix is to pass the function the addresses of x and y. C still passes those addresses by value (the function gets copies of the pointers), but a copy of an address points at the same place as the original. Dereferencing it reaches the caller's variable.

Three pieces have to line up for this to work:

  1. The parameter type is a pointer: int *a.
  2. The caller passes an address: swap(&x, &y).
  3. The function dereferences to read and write: *a = *b.

Forget the * inside the function and you'd be swapping the local pointer copies (which achieves nothing). Forget the & at the call and the compiler complains that you passed an int where an int * was expected. Read that warning carefully: it's almost always this mistake.

You've been doing this since lesson 2

scanf("%d", &n) needs the & for exactly this reason. scanf has to store a value into your variable, and the only way a C function can do that is if you hand it the variable's address. When you see & at a call site, read it as "this function may change this variable".

Output parameters: returning more than one value

A C function can only return one value. When you need more, the standard trick is an output parameter: the caller passes the address of a variable, and the function fills it in.

Notice that q and r don't need initial values: divmod only writes to them. A good habit is to name output parameters clearly (out_quotient, result) and put them at the end of the parameter list, so callers can tell inputs from outputs at a glance.

The success-flag pattern

A very common shape in C (and in scanf itself) is: return whether it worked, and deliver the actual result through a pointer. That separates "the answer" from "was there an answer?", which matters when every possible return value could be a legitimate result.

Try editing the input. scanf follows the same pattern: it returns how many items it successfully converted, and writes the values through the pointers you gave it. That's why the loop checks == 2. (Integer division truncates towards zero in C, so -9 / 4 is -2.)

What if the caller passes NULL?

Dereferencing a NULL output pointer is undefined behaviour (in practice, a crash). Some functions document "the pointer must not be NULL" and leave it to the caller; others check with if (result != NULL) and treat the output as optional. Either is fine, but decide, and write it in a comment above the function.

const pointers: "I promise only to look"

Passing a pointer gives a function the power to modify your data, even when all it needs is to read it. For arrays you have no choice, since an array argument is always passed as a pointer. So C lets the function promise not to write: declare the parameter as a pointer to const.

Read const int *values right to left: "values is a pointer to an int that is const". You can move the pointer, but you can't change the ints through it. This does two jobs:

  • It documents intent. A caller seeing const int * knows their array comes back untouched. Seeing plain int *, they should assume it might be modified.
  • It catches bugs. If you accidentally write through the pointer, the compiler stops you.

You can pass a plain int * to a const int * parameter freely (adding a promise is always safe). Going the other way, from const int * to int *, gets a warning, because it would throw the promise away. The standard library uses this everywhere: size_t strlen(const char *s) tells you strlen won't modify your string.

Where the const goes matters

const int *p (pointer to const int) means you can't change *p. int *const p (const pointer to int) means you can't change p itself. For parameters you almost always want the first. Advanced Pointers covers all the combinations.

Returning a pointer

Functions can return pointers too. The single question to ask is: will the thing it points to still exist after the function returns? Here are the cases where the answer is yes.

A pointer into the caller's data

If the caller handed you an array, the array outlives your function, so pointing into it is safe. This is a great way to return "where" something is, and lets the caller modify it in place:

Look at the standard library and you'll find many functions like this: strchr(s, c) returns a pointer to the first c in s, or NULL if there isn't one.

A pointer to static data

A local variable declared static isn't stored in the function's frame. It's created once, before the program starts, and lives until the program ends. Returning its address is legal. String literals are static too, so returning one is fine:

The catch with a static buffer is that there's only one of it: every call overwrites the previous result. printf("%s %s", format_seconds(1), format_seconds(2)) prints the same text twice. Use the result before calling again (or copy it).

Never: a pointer to a local variable

Dangling pointer to a local

A function's ordinary local variables live in its stack frame, and the frame is destroyed the moment the function returns. A pointer to one of them is left pointing at memory that no longer belongs to anything: a dangling pointer. Using it is undefined behaviour.

The nasty thing about this bug is that it often seems to work. The bytes where n lived usually still hold 42 right after the return, because nothing has overwritten them yet. Call another function (even printf) and that stack space gets reused, and the value changes underneath you. Some compilers, knowing it's UB, simply return NULL instead, turning it into a crash.

Fortunately, the compiler catches the obvious version (GCC and Clang warn about it by default, even without -Wall). GCC says "function returns address of local variable" and Clang says "address of stack memory associated with local variable 'n' returned". Treat that warning as an error, every time. But the compiler can't catch every disguise: int *p = &n; return p; may slip through without a warning, so the real defence is asking the lifetime question above.

The same applies to local arrays, which is the version beginners hit most often:

To fix it, either let the caller supply the buffer (void make_greeting(char *out, size_t size, const char *name), the pattern used by snprintf and fgets), make the buffer static with the caveats above, or malloc it and make the caller free it.

Looking ahead: big things go by pointer

There's one more reason to pass pointers that you'll meet in the Structs lesson. Passing by value copies the argument, which is nothing for an int but can be a lot of bytes for a large struct. So C programmers routinely pass structs as const struct Thing * even when the function only reads them: you get the efficiency of passing one address, and the const keeps the safety of a copy.

Exercises

Sort three variables

Write order(int *a, int *b), which swaps the two values if *a > *b, so that afterwards *a <= *b. Then complete sort3 using only calls to order so that x <= y <= z.

Hint

Inside sort3, x, y and z are already pointers, so pass them straight on: order(x, y), no &. Order x,y, then y,z (the largest is now in z), then x,y again.

Min and max in one pass

Write min_max, which takes a read-only array and its length (at least 1) and reports both the smallest and largest values through the output parameters out_min and out_max.

Hint

Start both lo and hi at a[0] (not at 0, or an all-positive or all-negative array goes wrong), loop from index 1, and at the end write *out_min = lo; and *out_max = hi;.

Find and replace through a returned pointer

The program reads 7 numbers into an array and then a target value. Write find_first, which returns a pointer to the first element equal to target, or NULL if there isn't one. main uses it to replace the first match with -1, so with the given input it prints found at index 2 and then the updated array.

Hint

Loop over the array; as soon as a[i] == target, return &a[i]; (or a + i). If the loop finishes, return NULL;. Returning a pointer into a is safe because the array belongs to main.

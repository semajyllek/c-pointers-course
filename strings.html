Strings

C has no built-in string type. A string is simply an array of char with a zero byte marking the end. That one convention explains how every string function works, why you must always leave room for one extra byte, and how a careless copy can overwrite memory it doesn't own.

A string is a char array ending in '\0'

Each char holds one character as a small number (its character code, so 'A' is 65 in ASCII). A string is a run of those chars followed by the null character, written '\0', whose value is 0. The null character isn't printed; it's a marker that says "the string stops here". Any array of chars that has a '\0' in it can be used as a string, and the string is everything before the first '\0'.

That's why a string always needs one more byte than its visible length. The literal "hi" takes 3 bytes: 'h', 'i', '\0'. The compiler adds the terminator to every string literal for you.

104 and 105 are the ASCII codes for h and i; the third byte is the terminator, code 0. A char is just a small integer, so %d prints its code and %c prints the character it stands for.

Single quotes vs double quotes

They aren't interchangeable. char c = "a"; is wrong (the compiler will complain), and so is passing 'a' where a string is expected. A fun precise detail: in C (unlike C++), a character constant like 'a' actually has type int, so sizeof 'a' is usually 4. It only becomes one byte once you store it in a char.

Declaring string arrays

The last line is a nasty trap. C lets you initialise an array with a literal that exactly fills it, silently dropping the terminator. e is five chars with no '\0', so anything that treats it as a string will run past the end looking for one. Leave the size out, or make sure it's at least one more than the length.

strlen vs sizeof

strlen measures the string; sizeof measures the container. They're only related by strlen(s) < sizeof s, since there must be room for the terminator.

strncpy looks like a safe strcpy, but it isn't really a string function: if the source is too long it stops after n chars without writing a '\0', as above. Always terminate manually, or better, use snprintf.

snprintf: the safe way to build strings

snprintf works like printf but writes into an array. You tell it the array's size, and it will never write past it: if the result is too long, it's cut short and still properly terminated. It returns the length the full result would have had, so you can detect truncation.

Comparing: strcmp, not ==

This compiles, and it's wrong:

== on two arrays asks whether they are the same array in memory (you'll see exactly why in Pointers & Arrays), and two separate arrays never are, whatever they contain. To compare contents, use strcmp(a, b), which walks both strings and returns:

  • 0 if they're equal,
  • a negative number if a comes first,
  • a positive number if b comes first.

The standard only promises the sign, not that it's −1 or 1, so test < 0, == 0 or > 0, never == -1. And because "equal" is 0, which is false, if (strcmp(a, b)) means "if they're different". Write == 0 explicitly.

Note the last two: strcmp compares character codes, so every uppercase letter sorts before every lowercase one, and a string sorts before any longer string it's a prefix of (because its '\0' is smaller than any letter).

Reading a line of input with fgets

scanf("%s", buf) reads a single word (it stops at a space) and, without a width like %19s, will happily write past the end of buf. For reading a whole line, use fgets:

It reads at most sizeof buffer - 1 characters, stops after a newline, and always adds the '\0'. Two details to handle:

  • The newline is kept. If the user typed Ada and pressed Enter, the buffer holds "Ada\n". You usually want to strip it.
  • It can fail. At end of input it returns NULL (a special "nothing" value you'll meet properly in Pointer Basics), and the buffer shouldn't be used.

Edit the input box and run again. A popular one-line alternative for stripping the newline is name[strcspn(name, "\n")] = '\0';: strcspn returns the index of the first '\n', or the string's length if there isn't one, so it's safe either way.

Never use gets

Older tutorials use gets(buf). It has no way to know the buffer's size, so any long line overflows it. It was so dangerous it was removed from the language in C11. Use fgets.

Character tests: <ctype.h>

<ctype.h> classifies and converts single characters. The tests return non-zero (true) or 0 (false):

FunctionTrue for
isdigit(c)'0' to '9'

isalnum(c)letters or digits
isspace(c)space, tab, newline and other whitespace
isupper(c) / islower(c)upper- / lowercase letters

toupper(c) and tolower(c) return the converted character, or c unchanged if it isn't a letter.

Why (unsigned char)?

The ctype functions take an int that must be either EOF or a value representable as an unsigned char. On many systems char is signed, so a non-ASCII character such as é can be negative, and passing that is undefined behaviour. The cast makes your code correct for any input. For plain ASCII text it makes no difference.

Buffer overflows

Every string function that writes (strcpy, strcat, scanf("%s"), your own loops) trusts you to have made the destination big enough. If you haven't, it writes straight past the end of the array:

Buffer overflow: undefined behaviour and a classic security hole

Writing past the end of a char array is out-of-bounds access, so it's undefined behaviour. The extra bytes land on whatever is next in memory: other variables, or the bookkeeping the program uses to return from the current function. Attackers have exploited exactly this for decades, carefully crafting over-long input to take control of programs. The defences are simple: know your buffer sizes, count the '\0', prefer snprintf and fgets, which take the size, and give scanf a width (%19s for a 20-byte array).

Common mistakes

  • Forgetting the extra byte: a 5-letter word needs char w[6].
  • Comparing with ==: use strcmp(a, b) == 0.
  • Assigning with =: s = "new"; doesn't compile for an array; use strcpy or snprintf.
  • Mixing 'x' and "x": one char versus a two-byte string.
  • Forgetting fgets keeps the newline, so strcmp(input, "yes") fails because the input is "yes\n".
  • Calling strlen in a loop condition, as in i < strlen(s). It's correct but rescans the string every iteration; store the length once, or loop until s[i] == '\0'.

Count the vowels

Write int count_vowels(const char s[]) that returns how many vowels (a, e, i, o, u) a string contains, counting both upper- and lowercase. Walk the string until '\0'.

Hint

Loop with for (int i = 0; s[i] != '\0'; i++). Convert each character with tolower first, so you only have to check five lowercase letters. A switch with five cases also works nicely.

Write your own strlen

Implement int my_strlen(const char s[]) without using <string.h>. It should return the number of characters before the terminator.

Hint

Start a counter at 0 and keep incrementing it while s[counter] isn't '\0'. When the loop stops, the counter is the index of the terminator, which is exactly the length. Note the last test: the array is 32 bytes, but the string is whatever comes before the first '\0'.

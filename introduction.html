Pointer Basics

Every variable lives somewhere in memory, and that somewhere has an address. A pointer is a variable whose value is one of those addresses. That one idea is behind most of what makes C powerful, and most of what makes it dangerous.

Memory is a row of numbered boxes

Think of your program's memory as a very long row of bytes, each with a number: its address. When you write int x = 10;, the compiler reserves a few bytes (usually 4 for an int), puts 10 in them, and remembers where they are.

Why the (void *)?

%p is the format specifier for printing an address. Strictly speaking it expects a void *, so we cast. You'll learn exactly what void * means in Advanced Pointers.

The * means two different things

This trips up nearly everyone at first:

  • In a declaration (int *p;), * means "p is a pointer".
  • In an expression (*p = 25;), * means "go to the address in p".

So int *p = &x; is a declaration with an initialiser. It sets p (not *p) to &x.

NULL: pointing at nothing

A pointer that doesn't point anywhere yet should be set to NULL. You can test for it before dereferencing, and dereferencing NULL reliably crashes instead of silently corrupting memory.

Never dereference an uninitialised pointer

int *p; *p = 5; writes 5 to a random address. It might crash, it might corrupt another variable, or it might appear to work until it doesn't. Always initialise pointers, either to a real address or to NULL.

Pointers have types for a reason

Every address is just a number, so why does C care whether it's an int * or a double *? Because dereferencing has to know how many bytes to read and how to interpret them. *p on an int * reads 4 bytes as an integer; on a double * it reads 8 bytes as a floating-point number. The type is also what makes pointer arithmetic work, which is the next lesson.

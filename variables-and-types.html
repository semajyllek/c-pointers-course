Variables & Types

A variable is a named piece of memory. In C, every variable has a type that is fixed when you declare it, and the type decides how many bytes it occupies, which values it can hold, and what operations make sense on it. Getting comfortable with types is the foundation for everything else, pointers included.

Declaring and initialising

To create a variable you declare it: write the type, then the name. You can give it a starting value in the same statement, which is called initialising it:

Notice that = here means assignment ("store this value"), not mathematical equality. age = age + 1 reads the current value, adds one, and stores the result back.

Variable names can contain letters, digits and underscores, but can't start with a digit, and they're case-sensitive (count and Count are different variables). You also can't use C keywords like int or return as names. Prefer descriptive names: total_price beats tp.

Declare near first use

Old C code declares every variable at the top of a function, because C89 required it. Since C99 you can declare a variable anywhere in a block, and it's usually clearer to declare it right where you first need it, already initialised.

There are also size variants of int: short, long and long long. The standard only guarantees minimum ranges: short and int are at least 16 bits, long at least 32, long long at least 64. On today's common desktop systems int is 32 bits and long is 64 bits on Linux and macOS but 32 bits on Windows.

char is a small integer

A char doesn't really store a letter. It stores a number, and by convention that number is a character code. Almost every system uses ASCII codes for the basic characters, where 'A' is 65, 'a' is 97 and '0' is 48. A character in single quotes is just a convenient way to write that number. 'A' is not "A"

Single quotes make a single character (an integer). Double quotes make a string, a sequence of characters ending in a hidden zero byte. They're different types and aren't interchangeable. You'll learn strings properly in a later lesson.

One more quirk: whether plain char is signed or unsigned is implementation-defined. On x86 it's usually signed (−128 to 127); on ARM it's usually unsigned (0 to 255). If you need a byte with a guaranteed range, write signed char or unsigned char explicitly.

float vs double

Both store numbers with a fractional part, in binary floating-point. double has roughly twice the precision of float, and it's the default: a literal like 3.14 is a double, while 3.14f is a float. Unless you have a specific reason (huge arrays, graphics hardware), use double.

Floating-point numbers are approximations. Most decimal fractions, like 0.1, can't be represented exactly in binary, so tiny errors creep in:

This isn't a C bug; every language using IEEE 754 floating-point behaves the same way. The practical lesson: never test floating-point numbers for exact equality, and never use them for money (count cents in an integer instead).

How big is a type? sizeof

The sizeof operator gives the size of a type or a variable in bytes. Its result has type size_t, an unsigned integer type, which you print with %zu. Write sizeof(type) with parentheses for a type; for a variable, sizeof x works too.

On the 64-bit Linux machine this runs on you'll see 1, 2, 4, 8, 8, 4, 8, 8. Those are typical values, not guaranteed ones. The only size the standard pins down is sizeof(char), which is 1 by definition. Code that assumes int is 4 bytes usually works, but if you need an exact width, <stdint.h> provides types like int32_t and uint8_t.

Signed and unsigned

Integer types are signed by default: they can hold negative numbers. Put unsigned in front and the same bits are used for non-negative values only, roughly doubling the maximum. With a 32-bit int:

Overflow: unsigned wraps, signed is undefined

What happens when a calculation goes past the end of the range? The answer is different for unsigned and signed types, and it's one of the most important rules in C.

Unsigned arithmetic wraps around, like a car's odometer. The standard defines it as arithmetic modulo 2N, so it's perfectly well-defined:

Signed overflow is undefined behaviour. The standard says nothing about what happens if an int calculation exceeds INT_MAX. It often appears to wrap to a large negative number, but you can't rely on that: optimising compilers assume signed overflow never happens and may transform your code in surprising ways because of it.

What "undefined behaviour" means

Undefined behaviour (UB) means the C standard places no requirements at all on what your program does. It might crash, give a plausible-looking wrong answer, or work perfectly today and break when you change compiler flags. It is not "implementation-defined" (where each compiler must pick and document a behaviour); it's a bug. You'll meet several kinds of UB in this course, and the rule is always the same: don't do it.

Mixing signed and unsigned

When you compare or combine a signed and an unsigned int, the signed one is converted to unsigned. So -1 < 1u is false: −1 becomes 4,294,967,295. -Wextra warns about signed/unsigned comparisons; take those warnings seriously.

Constants with const

Add const to a declaration and the variable becomes read-only after it's initialised. Any attempt to assign to it is a compile error. Use it for values that shouldn't change: it documents your intent and lets the compiler catch mistakes.

Uncomment the last assignment and run it to see the error. Because a const must get its value when it's declared, you always initialise it on the same line.

Why the &?

The & in &a is the address-of operator. C passes arguments to functions by value: the function gets a copy. If you wrote scanf("%d", a), scanf would receive a copy of a's current (garbage) value, which is useless; it needs to know where a lives so it can write the number into it. &a hands it that location. You'll understand this fully in the Pointer Basics lesson; for now, remember that scanf needs an & before each plain variable.

Forgetting & is a classic crash

scanf("%d", a); compiles (with a warning, if warnings are on) and then treats a's garbage value as an address to write to. That's undefined behaviour and usually a crash.

A few more details:

  • Check the return value. scanf returns how many items it successfully read. If the user types abc where a number was expected, it returns 0 and leaves your variable untouched. The example above checks for exactly 2.
  • Whitespace is skipped. %d skips spaces and newlines before the number, so 7 5, 7   5 and 7 on one line with 5 on the next all work.
  • %lf for double. Here scanf and printf differ: printf uses %f for both float and double, but scanf needs %f for float and %lf for double, because it writes through the address and must know the exact size.
  • " %c" for a character. Unlike %d, %c does not skip whitespace, so it would happily read a leftover newline. A space before it in the format string (" %c") skips any whitespace first.

Uninitialised variables hold garbage

When you declare a local variable without initialising it, C does not set it to zero. It holds whatever bits happened to be in that memory before, so its value is indeterminate. Reading it is a bug, and for many local variables it's undefined behaviour.

The frustrating thing about this bug is that it often seems to work: the garbage happens to be 0 in a small test program, and then a different value shows up once the program grows. Make it a habit to initialise every variable when you declare it. Compiling with -Wall catches many (not all) cases with a "may be used uninitialized" warning.

Globals are the exception

Variables declared outside any function (globals) and static variables are automatically initialised to zero. Only ordinary local variables start out as garbage. Still, an explicit = 0 makes your intent obvious.

Watch it wrap

An unsigned char is a byte that holds 0 to 255. Starting from the given value, add 1 and print, then subtract 2 from zero and print. Use %d for both (an unsigned char is promoted to int when passed to printf). Expected output:

255 + 1 = 0
0 - 2 = 254
Hint

Storing a value that's out of range into an unsigned type keeps it modulo 256 here: 256 becomes 0, and −2 becomes 254. Assign back into the variables, then print them.

Structs, Enums & Unions

Arrays group many values of the same type. Most real data isn't like that: a student has a name, an ID and a grade; a point has an x and a y. A struct bundles related values of different types into one new type you can pass around, copy and point to. Along with its cousins, enums and unions, it's how C programs model the world.

Defining a struct

A struct definition describes a new type: a list of named members (also called fields), each with its own type.

A few things to notice:

  • The type's name is struct Point, both words. Point on its own is just the tag (we'll fix the verbosity with typedef shortly).
  • Defining the struct doesn't create any variables or use any memory. It's a blueprint. struct Point a; creates an actual object.
  • Designated initialisers (.x = …), added in C99, are the clearest way to initialise a struct. They don't depend on member order, so they keep working if someone reorders or adds members. Any member you don't mention is set to zero.
  • Like any local variable, a struct with no initialiser has garbage in its members until you assign them.

Structs are values: assignment copies

Unlike arrays, structs behave like ordinary values. Assigning one struct to another copies every member, and passing a struct to a function copies it too. You can also return a struct from a function.

Returning m is fine, unlike returning a pointer to a local, because the value is copied out to the caller before the frame disappears.

You can't compare structs with ==

if (a == b) is a compile error for structs. Compare member by member, or write a function like bool point_eq(struct Point a, struct Point b). (Don't use memcmp for this either: padding bytes, covered below, can differ even when every member matches.)

Interestingly, an array inside a struct is copied along with the struct. struct Buf { char text[64]; }; can be assigned with =, even though bare arrays can't.

Pointers to structs and ->

Since passing a struct copies it, a function that needs to modify a struct takes a pointer to it, exactly like swap in Pointers & Functions. Accessing members through a pointer is so common that C has a dedicated operator for it:

ExpressionMeaning
s.xmember x of the struct s
p->xmember x of the struct that p points to. Exactly the same as (*p).x

Why not just write *p.x? Because . binds tighter than *, so that means *(p.x), "dereference the member x of p", which is a compile error since p isn't a struct. The parentheses in (*p).x are required, and -> saves you from writing them.

In practice, -> mostly appears in functions that receive a struct pointer. Use a plain pointer when the function should modify the struct, and const when it only reads it. That second case is the pattern promised in the last lesson: passing one address instead of copying a big struct, with const keeping it safe.

Memory layout and padding

Members are stored in the order you declare them, but not necessarily packed tightly. Most CPUs access an int fastest (and some only at all) when its address is a multiple of 4, its alignment. To keep each member aligned, the compiler may insert unused padding bytes between members and at the end.

On typical x86-64 and ARM systems, struct Loose is 12 bytes even though its members only total 6: three bytes of padding after a so that b starts at offset 4, and three more at the end so that in an array of these structs, every element's b stays aligned. Reordering the members gives struct Tight, typically 8 bytes.

The exact amount of padding is implementation-defined: the C standard only promises that members appear in declaration order, the first member is at offset 0, and there's no padding before the first member. So:

  • Never hard-code a struct's size. Always use sizeof.
  • When memory matters (millions of structs), ordering members from largest to smallest alignment usually minimises padding.
  • Don't write a struct's raw bytes to a file or network and expect another compiler or machine to read them back the same way. You'll see better approaches in File I/O.

Enums: named integer constants

An enum defines a set of named integer constants. It's the right tool whenever a value is "one of a fixed list of options": a direction, a state, a colour, a kind of token.

  • By default the first constant is 0 and each one after is one more than the previous. You can assign explicit values, and any constant without one continues counting from the previous: enum { A = 5, B, C } gives B = 6, C = 7.
  • Enum constants are just ints, so you can print them with %d and do arithmetic on them. C does not stop you from assigning any integer to an enum variable; it's a convenience and documentation tool, not a strict type.
  • Enums pair beautifully with switch. With -Wall, if you switch over an enum and forget one of its constants (and have no default), the compiler warns. Add a new direction later and it points you to every switch that needs updating.
Why not just use #define or magic numbers?

if (state == 2) tells the reader nothing; if (state == STATE_RUNNING) tells them everything. Enums give you names like #define does, but they also group the options under one type, follow normal scoping rules, show up by name in debuggers, and enable those switch warnings.

Unions: one space, several interpretations

A union looks like a struct, but all its members share the same memory, starting at the same address. It's only as big as its largest member (plus any padding), and only one member holds a meaningful value at a time: the one you wrote last.

Reading a member other than the one last written reinterprets the raw bytes as the other type, which is rarely what you want. So a union on its own is risky: nothing records which member is currently valid. The standard solution is a tagged union: wrap the union in a struct together with an enum that says which member is in use.

Each shape stores only the data its kind needs, all in the same bytes, and the kind tag tells area how to read them. (With 8-byte doubles that's typically 24 bytes per shape: 4 for the tag, 4 of padding, and 16 for the largest union member.) Tagged unions are how C programs represent things like JSON values, tokens in a compiler, or messages in a protocol. Always set the tag whenever you set the union, and always check the tag before you read.

Control Flow

So far every program has run straight from the top of main to the bottom. Real programs make decisions and repeat work. C gives you a small, sharp set of tools for that: if and switch to choose, and while, do-while and for to loop. Master these and you can write almost any algorithm.

Making decisions: if

An if statement runs a block of code only when its condition is true. Add else for what to do otherwise, and chain else if to test several conditions in turn. Try different scores in the input box:

The conditions are checked top to bottom, and only the first true one runs; the rest are skipped. That's why the second test can be just score >= 80: if we get there, we already know the score is below 90. Put the conditions in the wrong order (>= 70 first) and everyone above 70 gets a C.

What counts as true?

C's rule is simple: in a condition, zero is false and every other value is true. A condition doesn't have to be a comparison; any expression with a value will do. That's why you'll often see idioms like these:

Choosing among many: switch

When you're comparing one integer value against a list of constants, switch is often cleaner than a long else if chain:

How it works:

  • The expression in switch ( ) must be an integer type (which includes char). You can't switch on a string or a double.
  • Each case label must be a constant, like 3 or 'q'. No variables, no ranges.
  • Execution jumps to the matching label and runs from there. default catches everything that didn't match.
  • break leaves the switch.

Repeating: the while loop

A while loop checks its condition, runs the body if it's true, and then goes back and checks again. It stops the first time the condition is false. If the condition is false to begin with, the body never runs at all.

while is the natural choice when you don't know in advance how many times you'll loop: "keep doubling until we pass 100", "keep reading until the input runs out".

Counting: the for loop

Most loops follow the same pattern: set up a counter, check it, update it. A for loop puts all three parts on one line:

Any for loop can be rewritten as a while loop and vice versa; choose whichever reads better. Use for when there's a clear counter, and while when you're looping until something happens. A few more things to know:

  • A variable declared in the initialise part (for (int i = 0; …)) exists only inside the loop. That's usually what you want.
  • The update doesn't have to be i++: i += 2, i-- and i *= 2 are all fine.
  • Any of the three parts can be empty. for (;;) loops forever (until a break).

Leaving early: break and continue

Two keywords let you change a loop's flow from inside the body:

  • break exits the loop immediately. Execution continues after the loop.
  • continue skips the rest of this iteration and goes on to the next one. In a for loop, the update still runs.

while (1) with a break inside is a common, perfectly respectable pattern when the exit test fits naturally in the middle of the loop. Note that break only leaves the innermost loop or switch it's inside. That matters for nested loops, and it's also why a break inside a switch inside a loop leaves the switch, not the loop.

Loop bugs everyone writes once

The infinite loop

If nothing in the body ever makes the condition false, the loop never ends. The usual cause is forgetting the update:

A sneakier version is a stray semicolon. while (i < 10); (note the ;) is a loop whose body is the empty statement, so it spins forever without ever reaching the block below it. The same mistake after a for or an if silently detaches the body. If a program seems to hang, look for these first. (On this site, a program that runs too long is stopped automatically.)

Off by one

"Run this 10 times" is for (int i = 0; i < 10; i++), counting 0 to 9. Write <= by habit and you get 11 iterations. With arrays (two lessons from now) that extra iteration reads past the end, which is undefined behaviour. A useful check: a loop from a while i < b runs exactly b - a times.

Prefer half-open ranges

The convention "start at 0, stop when i < n" (the range [0, n), including 0 but excluding n) is the idiom of C. It matches how arrays are indexed, the count is just n, and empty ranges (n == 0) work with no special case. When you see <= in a loop condition, give it a second look.

Hint

Use an if / else if chain with %. Order matters: test for "multiple of both" (i % 15 == 0) first, or 15 will be caught by the multiple-of-3 test and print just Fizz.

Number triangle

Read a height h, then print h rows where row r contains the numbers 1 to r, separated by spaces. Use nested for loops. For the input 5:

1

Hint

The outer loop counts row from 1 to h. Inside it, a second loop counts from 1 to row, printing each number followed by a space. After the inner loop, print \n. (Trailing spaces at the end of a line are ignored by the checker.)

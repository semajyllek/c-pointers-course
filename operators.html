Operators & Expressions

An expression is anything that produces a value: 42, x, price * 1.2, a > b. Operators are how you build them. Most will look familiar from maths, but C has a few rules, especially around integer division, types and precedence, that surprise everyone once. Better that it happens here.

Yes, 7 / 2 is 3. That's the first big surprise.

Integer division and the remainder

When both operands of / are integers, C performs integer division: the result is an integer, and any fractional part is thrown away. It isn't rounded; it's cut off. The % operator gives you what was thrown away, the remainder:

The pair / and % always satisfies (a / b) * b + a % b == a. That makes % wonderfully useful: n % 2 == 0 tests whether n is even, n % 10 gives the last decimal digit, and n / 10 chops it off.

Negative numbers truncate toward zero

Since C99, integer division always truncates toward zero, so -7 / 2 is -3, not -4. And because of the identity above, the remainder takes the sign of the left operand: -7 % 2 is -1. This is different from Python, where -7 // 2 is -4 and -7 % 2 is 1.

Odd-number tests and negatives

Because -3 % 2 is -1, the test n % 2 == 1 is false for negative odd numbers. Write n % 2 != 0 to test for odd numbers.

Dividing by zero

Integer division or remainder by zero is undefined behaviour. On most machines it crashes the program. (So does INT_MIN / -1, since the answer doesn't fit in an int.) Check the divisor first whenever it could be zero.

Mixing types: promotion and casts

If either operand of an arithmetic operator is a floating-point type, the other is converted to match before the operation, and the result is floating-point. So 7 / 2.0 is 3.5. These automatic usual arithmetic conversions always convert towards the "bigger" type: int to double, float to double, and so on. (Small types like char and short are also promoted to int before any arithmetic.)

The fix is a cast: (double)sum converts sum to a double for that expression, so the division is done in floating-point. The cast applies to sum only, but that's enough; count is then promoted automatically.

Be careful where you put the cast: (double)(sum / count) is still 4.0, because the parentheses make the integer division happen first.

Casting the other way, from floating-point to integer, truncates toward zero: (int)3.99 is 3 and (int)-3.99 is -3. (If the value is too large to fit in the target integer type, that's undefined behaviour.)

Assignment and compound assignment

In C, assignment is itself an expression: x = 5 stores 5 and has the value 5. That's why a = b = 0; works (it's a = (b = 0)). It's also behind one of the most famous C bugs, which we'll see below.

"Update a variable using its own value" is so common that C has shorthand for it:

ShorthandMeans
x += 5x = x + 5
x -= 5x = x - 5
x *= 5x = x * 5
x /= 5x = x / 5
x %= 5x = x % 5

There are also &=, |=, ^=, <<= and >>= for the bitwise operators. Note that x *= a + b means x = x * (a + b): the whole right-hand side is evaluated first.

Increment and decrement

++ adds one to a variable and -- subtracts one. Each comes in two forms, and the difference is the value of the expression:

  • Prefix ++i: increment i, and the expression's value is the new value.
  • Postfix i++: increment i, but the expression's value is the old value.

When ++ or -- is a statement on its own, like count++;, the two forms are identical. The difference only matters when you use the value.

Don't modify a variable twice in one expression

Lines like i = i++;, i++ + i++ or printf("%d %d", i, i++) are undefined behaviour. C doesn't say in which order the parts of an expression are evaluated, and modifying a variable while also reading or modifying it elsewhere in the same expression, without a sequence point in between, breaks the rules. Different compilers really do give different answers. The fix is simple: if you increment a variable, don't mention it again in the same expression.

Comparison operators

Comparisons produce an int: 1 if true, 0 if false. C has no separate boolean result type for them (bool is just a type you can store them in).

OperatorMeaning
==equal to
!=not equal to
< <=less than, less than or equal
> >=greater than, greater than or equal

One thing comparisons can't do is chain like in maths. 0 < x < 10 means (0 < x) < 10: the first comparison gives 0 or 1, and both are less than 10, so it's always true. Write 0 < x && x < 10 instead.

Like comparisons, they give 1 or 0. Any nonzero operand counts as true, so !5 is 0 and !0 is 1.

&& and || also short-circuit: they evaluate left to right and stop as soon as the answer is known. If the left side of && is false, the right side is never evaluated; if the left side of || is true, the right side is skipped. When in doubt, add parentheses

Nobody remembers the whole precedence table, and readers of your code won't either. Parentheses cost nothing and make your intent unambiguous. Use them freely, especially around bitwise operations and whenever you mix && with ||.

Bitwise operators

Bitwise operators work on the individual bits of an integer. They're how C talks to hardware registers, packs many yes/no flags into one number, and implements fast arithmetic tricks. Using 8-bit values for readability:

OperatorNameExample (binary)Result
a & bAND: 1 where both bits are 11100 & 10101000
a | bOR: 1 where either bit is 11100 | 10101110
a ^ bXOR: 1 where the bits differ1100 ^ 10100110
~aNOT: flips every bit~0000110011110011
a << nshift left by n (multiplies by 2n)0011 << 21100

Don't confuse & with &&, or | with ||. 6 && 1 is 1 (both are true), but 6 & 1 is 0 (110 and 001 share no bits).

Example: permission flags

A classic use is storing several on/off settings in one integer, one bit each. Give each flag its own bit with 1u << n, then:

  • set a flag with |=,
  • clear it with &= ~,
  • toggle it with ^=,
  • test it with &.

This is exactly how Unix file permissions work: chmod 755 is three groups of these bits.

Use unsigned types for bit manipulation

Shifting a 1 into or past the sign bit of a signed int, or left-shifting a negative number, is undefined behaviour, and right-shifting a negative number is implementation-defined. Shifting by a negative amount or by at least the type's width (e.g. x << 32 on a 32-bit int) is undefined for any type. Stick to unsigned values and you avoid nearly all of it.
